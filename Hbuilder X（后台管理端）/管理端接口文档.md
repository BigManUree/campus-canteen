## 基础说明

### Base URL

- 开发环境：`http://localhost:8000/api`
- 生产环境：根据实际部署地址配置

### 认证方式

所有管理端接口均需在请求头中携带 JWT Token：

```http
Authorization: Bearer {token}
```

### 适用角色

- `admin` / `sys_admin`：系统管理员，拥有全部管理权限
- `merchant` / `canteen_admin`：档口管理员，可管理自己所属档口的数据

### 权限约定

文档中的权限说明按以下规则理解：

- **管理员**：`admin`、`sys_admin`、`merchant`、`canteen_admin`
- **系统管理员**：`admin` 或 `sys_admin`
- **档口管理员**：`merchant` 或 `canteen_admin`
- 若接口涉及档口数据，档口管理员通常仅可操作自己档口的数据

## 认证授权

### 1. 管理员登录

- **接口地址**：`POST /auth/login`
- **接口说明**：管理端与普通端共用登录接口，通过返回的 `role` 字段判断是否可进入管理端
- **权限要求**：无需登录

#### 请求参数

```json
{
  "username": "admin",
  "password": "password123"
}
```

#### 响应示例

```json
{
  "token": "jwt_token_string",
  "expireIn": 7200,
  "userInfo": {
    "user_id": 1,
    "username": "admin",
    "nickname": "管理员",
    "role": "sys_admin",
    "status": 1
  }
}
```

#### 说明

- 前端登录成功后应缓存 `token` 与 `userInfo`
- 只有 `sys_admin` 或 `canteen_admin` 可进入管理端

### 1. 获取管理端概览统计

- **接口地址**：`GET /statistics/overview`
- **权限要求**：管理员
- **接口说明**：用于管理端首页展示今日订单数、销售额、待处理订单等核心指标

#### 查询参数

无

#### 真实响应字段

```json
{
  "today_orders": 100,
  "today_sales": 5000.0,
  "today_users": 50,
  "pending_orders": 10
}
```

#### 说明

- 当前后端真实返回字段为：`today_orders`、`today_sales`、`today_users`、`pending_orders`
- 文档中曾出现过 `completed_orders`、`canceled_orders`、`avg_order_amount`、`growth_rate` 等扩展字段，但当前接口实现中**未返回**
- 前端请以真实返回字段为准

## 订单管理

### 1. 获取订单列表

- **接口地址**：`GET /order/list`
- **权限要求**：当前后端真实实现为“当前用户订单列表”接口；如需管理端订单筛选能力，需单独核对或补充后端实现

#### 查询参数

无

#### 真实响应结构

- 返回类型：`list[OrderOut]`
- **不是**分页结构
- 当前实现**不支持** `page`、`page_size`、`order_status`、`pay_status`、`order_no`、`start_date`、`end_date`、`canteen_id` 这些管理端筛选参数

#### 响应字段

```json
    "user_id": 1,

      "building": "A",

      "window_no": "01",

    "order_type": "pickup",
    "total_amount": 30.0,
    "discount_amount": 0,
    "pay_amount": 30.0,
    "pay_status": 1,
    "pay_time": "2024-01-01T10:00:00",
    "order_status": 1,

    "update_time": "2024-01-01T10:00:00",
    "items": []
  }

```

#### 说明

- 当前文档原先按“管理端订单列表”描述，但代码中 `GET /order/list` 实际是**用户自己的订单列表**
- 管理端真正可用的仍是：`GET /order/detail/{order_id}`、`PUT /order/status/{order_id}` 等带权限校验的接口
- 如果前端要做后台订单筛选页，建议后续补充独立管理端订单列表接口

### 2. 获取订单详情

- **接口地址**：`GET /order/detail/{order_id}`
- **权限要求**：已登录用户可查看自己的订单；管理员/档口管理员可查看有权限的订单

#### 路径参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `order_id` | int | 是 | 订单 ID |

#### 真实响应说明

返回 `OrderOut` 对象，主要字段包括：

- `order_id`
- `order_no`
- `user_id`
- `canteen_id`
- `canteen`
- `order_type`
- `total_amount`
- `discount_amount`
- `pay_amount`
- `pay_status`
- `pay_time`
- `order_status`
- `pickup_code`
- `pickup_time`
- `verify_time`
- `accept_time`
- `ready_time`
- `complete_time`
- `cancel_time`
- `cancel_reason`
- `delivery_address`
- `delivery_latitude`
- `delivery_longitude`
- `remark`
- `create_time`
- `update_time`
- `items`

#### 说明

- 当前后端会附带 `canteen` 档口信息
- 文档中提到的“用户信息、支付信息等完整对象”并非都作为嵌套对象返回，前端请按 `OrderOut` 实际字段取值

### 3. 更新订单状态

- **接口地址**：`PUT /order/status/{order_id}`
- **权限要求**：管理员

#### 路径参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `order_id` | int | 是 | 订单 ID |

#### 请求参数

```json
{
  "order_status": 2
}
```

#### 参数说明

- `0`：待确认
- `1`：制作中
- `2`：待取餐
- `3`：配送中
- `4`：已完成
- `5`：已取消

#### 常见错误

- `403`：需要管理员权限
- `404`：订单不存在
- `400`：订单状态不允许修改

### 4. 验证取餐码

- **接口地址**：`POST /order/verify/{order_id}`
- **权限要求**：管理员

#### 路径参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `order_id` | int | 是 | 订单 ID |

#### 查询参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `pickup_code` | string | 是 | 取餐码 |

#### 响应示例

```json
{
  "success": true,
  "message": "取餐码验证成功"
}
```

```json
  "email": "admin@example.com",

```

### 2. 获取用户列表

- **接口地址**：`GET /user/list`
- **权限要求**：管理员

#### 查询参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `page` | int | 否 | 页码 |
| `page_size` | int | 否 | 每页数量，最大 `1000` |
| `keyword` | string | 否 | 搜索关键词：`username`、`nickname`、`student_no` |
| `role` | string | 否 | 角色筛选 |
| `status` | int | 否 | 状态筛选：`0-禁用`、`1-启用` |

#### 真实响应结构

```json
{
  "items": [
    {
      "user_id": 1,
      "username": "user001",
      "phone": "13900139000",
      "email": "user@example.com",
      "nickname": "用户昵称",
      "avatar": "/uploads/avatar.jpg",
      "gender": 0,
      "student_no": "2024001",
      "department": "计算机学院",
      "role": "student",
      "status": 1,
      "create_time": "2024-01-01T10:00:00",
      "update_time": "2024-01-01T10:00:00"
    }
  ],
  "total": 100,
  "page": 1,
  "page_size": 20,
  "total_pages": 5
}
```

#### 说明

- 实际返回为 `PaginatedResponse[UserOut]`
- `role` 真实枚举包含：`student`、`merchant`、`admin`，同时兼容旧值 `user`、`canteen_admin`、`sys_admin`
- 字段中包含 `avatar`、`gender`、`department`、`update_time`，这些都建议前端按真实响应接收

### 3. 获取用户详情

- **接口地址**：`GET /user/detail/{user_id}`
- **权限要求**：系统管理员

### 4. 更新用户信息

- **接口地址**：`PUT /user/update/{user_id}`
- **权限要求**：系统管理员

#### 请求参数

### 7. 批量更新用户 / 批量删除用户（兼容接口）

- `description`
- `price`
- `original_price`

- `allergen`
- `calorie`
- `images`
- `stock`
- `sales`
- `status`

- `favorite_count`

- `update_time`
- `is_new`

| `merchant` / `canteen_admin` | 档口管理员，可访问自己档口相关的订单、菜品、统计、排队等接口 |
| `student` / `user` | 普通用户，不可访问管理端 |

### 权限建议

- **系统管理员**：用户管理、档口管理、分类管理、优惠券管理、活动管理、导出功能等
- **档口管理员**：订单处理、菜品管理、退款处理、评价管理、排队管理、部分统计查看
